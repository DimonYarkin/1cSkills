# 1C Report Development Guide (БСП/UNF Patterns)

## 1. Report File Structure

```
Reports/
└── MyReport/
    ├── MyReport.mdo              # Report metadata definition
    ├── ObjectModule.bsl          # Report logic (form events, composition)
    ├── ManagerModule.bsl         # Variants configuration, subsystem placement
    └── Templates/
        ├── ОсновнаяСхемаКомпоновкиДанных.dcs  # Main СКД schema (binary)
        ├── ОбразецОсновной.bin                # Sample report template
        └── ОбразецВариант2.bin                # Sample for variant 2
```

## 2. Report MDO Structure

```xml
<?xml version="1.0" encoding="UTF-8"?>
<mdclass:Report xmlns:mdclass="http://g5.1c.ru/v8/dt/metadata/mdclass" uuid="...">
  <name>MyReport</name>
  <synonym><key>ru</key><value>Мой отчёт</value></synonym>
  <defaultForm>CommonForm.ФормаОтчета</defaultForm>
  <mainDataCompositionSchema>Report.MyReport.Template.ОсновнаяСхемаКомпоновкиДанных</mainDataCompositionSchema>
  <defaultVariantForm>CommonForm.ФормаВариантаОтчета</defaultVariantForm>
  <variantsStorage>SettingsStorage.ХранилищеВариантовОтчетов</variantsStorage>
  <attributes uuid="...">
    <name>ЭтоОтчетУНФ</name>
    <type><types>Boolean</types></type>
  </attributes>
  <templates uuid="...">
    <name>ОсновнаяСхемаКомпоновкиДанных</name>
    <templateType>DataCompositionSchema</templateType>
  </templates>
  <templates uuid="...">
    <name>ОбразецОсновной</name>
    <templateType>BinaryData</templateType>
  </templates>
</mdclass:Report>
```

**Key fields:**
- `mainDataCompositionSchema` — points to the main СКД template
- `defaultForm` — `CommonForm.ФормаОтчета` (standard report form)
- `variantsStorage` — `SettingsStorage.ХранилищеВариантовОтчетов`

**Key rules:**
- `ВариантыНастроек()` returns array of `{Имя, Представление}` — name matches СКД variant key
- `НастроитьВариантыОтчета()` configures:
  - `Описание` — tooltip text
  - `Размещение` — where to show (subsystems, start page)
  - `ФункциональныеОпции` — visibility conditions
  - `ВидимостьПоУмолчанию` — default visibility

```1c
// Задаёт настройки формы отчета.
//
// Параметры:
//  Форма        - ФормаКлиентскогоПриложения
//  КлючВарианта - Строка, Неопределено
```

## 5. ОбработчикиСобытий — Standard Event Sequence

Every report ObjectModule implements these handlers:

| Handler | When Called | Purpose |
|---------|-----------|---------|
| `ОпределитьНастройкиФормы` | Form creation | Register form events |
| `ПриОпределенииНастроекОтчета` | Report init | Set tags, related fields |
| `ПриСозданииНаСервере` | Form creation | Delegate to `ОтчетыУНФ` |
| `ПриЗагрузкеВариантаНаСервере` | Variant load | Update filters, segments |
| `ПриЗагрузкеПользовательскихНастроекНаСервере` | User settings load | Transfer title params |
| `ПриКомпоновкеРезультата` | **Report generation** | Modify СКД, compose data |

## 6. ПриКомпоновкеРезультата — The Core Handler

This is where the report logic lives:

```1c
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)

    // Step 1: Modify СКД schema (add fields, modify queries)
    МодифицироватьСхемуДляВарианта();

    // Step 2: Set data parameters dynamically
    КомпоновщикНастроек.Настройки.ПараметрыДанных.УстановитьЗначениеПараметра(
        "НачалоПериода", НачалоПериода);
    КомпоновщикНастроек.Настройки.ПараметрыДанных.УстановитьЗначениеПараметра(
        "КонецПериода", КонецПериода);

    // Step 3: Process user settings
    ОтчетыУНФ.ОбъединитьСПользовательскимиНастройками(КомпоновщикНастроек);

    // Step 4: Standard composition (do NOT set СтандартнаяОбработка = Ложь)
    ОтчетыУНФ.ПриКомпоновкеРезультата(
        КомпоновщикНастроек, СхемаКомпоновкиДанных,
        ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка);

КонецПроцедуры
```

**CRITICAL:** Do NOT set `СтандартнаяОбработка = Ложь` unless doing fully custom composition.

## 7. Dynamic СКД Modification

### Add calculated field:
```1c
ВычисляемоеПоле = СхемаКомпоновкиДанных.ВычисляемыеПоля.Добавить();
ВычисляемоеПоле.ПутьКДанным = "ИмяПоля";
ВычисляемоеПоле.Выражение = "Выражение";
ВычисляемоеПоле.Заголовок = "Заголовок";
ВычисляемоеПоле.ТипЗначения = Новый ОписаниеТипов("Число");
```

### Add data set:
```1c
НаборДанных = СхемаКомпоновкиДанных.НаборыДанных.Добавить(Тип("НаборДанныхЗапросСхемыКомпоновкиДанных"));
НаборДанных.Имя = "НаборДанных1";
НаборДанных.Запрос = "ВЫБРАТЬ ... ИЗ ...";

```

### Set parameter value:
```1c
КомпоновщикНастроек.Настройки.ПараметрыДанных.УстановитьЗначениеПараметра(
    "ИмяПараметра", ЗначениеПараметра);
```

### Check selected resources:
```1c
ЗаполнитьРесурсыРекурсивно(Ресурсы, КомпоновщикНастроек.Настройки.Выбор.Элементы);
Если Ресурсы.Найти("ИмяРесурса") <> Неопределено Тогда
```

## 8. UNF Helper Module — ОтчетыУНФ

UNF provides a centralized helper module for reports:

| Method | Purpose |
|--------|---------|
| `ОтчетыУНФ.ПриКомпоновкеРезультата(...)` | Standard composition entry point |
| `ОтчетыУНФ.ОбъединитьСПользовательскимиНастройками(...)` | Merge user settings |
| `ОтчетыУНФ.ДобавитьСимволВалютыКЗаголовкамПолей(...)` | Add currency symbols |
| `ОтчетыУНФ.ФормаОтчетаПриСозданииНаСервере(...)` | Form initialization |
| `ОтчетыУНФ.ФормаОтчетаПриЗагрузкеВариантаНаСервере(...)` | Variant loading |
| `ОтчетыУНФ.ОбновитьВидимостьОтбораОрганизация(...)` | Toggle org filter |

| `ОтчетыУНФ.ПеренестиПараметрыЗаголовкаВНастройки(...)` | Title params |

## 10. Common СКД Patterns

### Period parameter:
```xml
<Parameter name="НачалоПериода">
  <ValueType>Дата</ValueType>
  <DefaultValue>НачалоПериода(ТекущаяДатаСеанса())</DefaultValue>
</Parameter>
```

### Resource (aggregation):
```xml
<Resource name="Сумма">
  <ValueType>Число</ValueType>
  <Expression>Сумма</Expression>
  <Role>Aggregate</Role>
</Resource>
```

### Calculated field with conditional:
```
ВЫБОР КОГДА Сумма > 0 ТОГДА (Сумма - Себестоимость) / Сумма * 100 ИНАЧЕ 0 КОНЕЦ
```

### Conditional formatting:
```1c
ЭлементУсловия = Настройки.УсловноеОформление.Элементы.Добавить();
ПолеУсловия = ЭлементУсловия.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
ПолеУсловия.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("ВаловаяПрибыль");
ПолеУсловия.ВидСравнения = ВидСравненияКомпоновкиДанных.Меньше;
ПолеУсловия.ПравоеЗначение = 0;
ЭлементУсловия.Оформление.УстановитьЗначениеПараметра("ЦветТекста", ЦветаСтиля.ЦветОтрицательногоЧисла);
```

## 11. Report Types in UNF

| Type | Example | СКД Complexity |
|------|---------|---------------|
| Register-based | Продажи, Закупки, ОстаткиТоваров | High (multiple data sets) |
| Document-based | ДвиженияДокумента | Medium (dynamic sets per registers) |
| Financial | Баланс, ФинансовыйРезультат | Very High (accounting schemas) |
| Simple | АктСверки, Ведомость | Low (single query) |

## 12. Best Practices

1. **Always use `ОтчетыУНФ.*` helpers** — don't reinvent composition logic
2. **Don't set `СтандартнаяОбработка = Ложь`** unless doing fully custom output
3. **One main СКД template** + binary samples per variant
4. **Variant keys must match** between ManagerModule and СКД
5. **Tags for search** — every variant should have descriptive tags
6. **Related fields for navigation** — link to справочники/документы from report cells
7. **Currency symbols** — use `ДобавитьСимволВалютыКЗаголовкамПолей` for money fields
8. **Functional options** — hide variants that require disabled subsystems

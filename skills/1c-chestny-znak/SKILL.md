# Честный Знак (ИС МП) в 1С:УНФ — операционный контракт для ИИ-агента

Маркировка товаров «Честный Знак» = **ИС МП** (Информационная система маркировки
продукции, также ИС МОТП / ГИС МТ) оператора **ЦРПТ**. В УНФ интеграция лежит в
библиотеке подсистем `ИнтеграцияИСМП` / `ОбменДаннымиИСМП` / `ШтрихкодированиеИСМП`.
Агент **не ходит в CRPT напрямую** — он работает с документами и данными УНФ
(через `unfAiAgent` HTTP), а обмен с ЦРПТ выполняют типовые модули 1С.

## 0. Три уровня API (не путать)

| Уровень | Хост | Для чего | Auth |
|---------|------|----------|------|
| **ИС МП / True API** | `api.markirovka.crpt.ru` (prod) / `api.markirovka.sandbox.crptech.ru` (test) | статусы КМ, продукция, документы, УПД, остатки | ключ сессии (ЭЦП) |
| **СУЗ / OMS** | тот же базовый хост, поддомен `oms` | заказы на эмиссию КМ, пул кодов, агрегация, отчёты | заголовок `clientToken` |
| **Локальный модуль ЧЗ (ЛМ ЧЗ)** | локальный сервис, порт **5995** (по умолчанию) | разрешительный режим, офлайн-проверка КМ на ККТ | `Basic` (логин/пароль админа) или `Token` (ПМСР) |

Базовый адрес (`ОбщегоНазначенияИСМПКлиентСервер.АдресСервера`):

```
prod:   markirovka.crpt.ru
test:   markirovka.sandbox.crptech.ru
```

HTTP-параметры (`ПараметрыОтправкиHTTPЗапросов`): порт `443`, SSL, таймаут `60` сек.
Поддомен: `api` (ИС МП), `oms` (СУЗ), `cdn` (площадки), `true-api` в пути = True API.

## 1. Авторизация

### 1.1 Ключ сессии ИС МП (ЭЦП организации)

`ИнтерфейсАвторизацииИСМПКлиентСервер.ПараметрыЗапросаКлючаСессии()`

| Поле | Значение |
|------|----------|
| `АдресЗапросаПараметровАвторизации` | `api/v3/auth/cert/key` |
| `АдресЗапросаКлючаСессии` | `api/v3/auth/cert/` |
| `ВремяЖизни` | `900` сек (15 мин) |
| `Порт` / SSL | `443` / да |

Поток: запрос `key` → подписание сертификатом организации → `POST api/v3/auth/cert/`
→ `token` (ключ сессии). Далее ключ идёт в query (`?token=...`) или заголовке.

Смежные оболочки ключа:
- `ПараметрыЗапросаКлючаСессии(Организация)` — ИС МП
- `ПараметрыЗапросаКлючаСессииСУЗ(ПараметрыСУЗ)` — СУЗ
- `ПараметрыЗапросаКлючаСессииИСМПРозница(Организация)` — розница / ЛМ ЧЗ

Требуется **сертификат ЭЦП** организации (КриптоПро / платформа 1С). Токен
хранится в параметре сеанса; актуализация — справочник
`ОтветственныеЗаАктуализациюТокеновАвторизацииИСМП`.

### 1.2 СУЗ (`clientToken`)

Все запросы СУЗ несут заголовок:

```
clientToken: <ТокенСУЗ>
```

Получение: `ИнтерфейсСУЗ.ЗапроситьТокен_V2(...)`. В запросах фигурирует
`omsId` (идентификатор станции управления заказами).

### 1.3 Локальный модуль ЧЗ

`ОбщегоНазначенияИСМПКлиентСервер.ПараметрыПодключенияЛокальногоМодуляЧЗ()`:

| Поле | Описание | Default |
|------|----------|---------|
| `Сервер` | адрес ЛМ | — |
| `Порт` | порт службы | **5995** |
| `ЗащищенноеСоединение` | https | `Ложь` |
| `Логин` / `Пароль` | администратор ЛМ (при установке) | — |
| `ТокенПМСР` + `ДатаДействияТокенаПМСР` | краткосрочный токен вместо Basic | — |
| `ФорматОбмена` | `ВерсииФорматаОбменаЛокальногоМодуляИСМП` (V1/V2) | — |

Заголовки ЛМ:
- `Authorization: Basic base64(логин:пароль)` **или** `Authorization: Token <ПМСР>`
- `X-ClientId: <ИдентификаторФискальногоНакопителя>` (опц.)
- `Accept: application/json`, `Accept-Charset: utf-8`

Инициализация: `api/v1/init` (V1) / `api/v2/init` (V2) — тело `{token: <ключСессииИСМПРозница>}`.

Настройки хранятся в РС `НастройкиПодключенияЛокальныхМодулейИСМП`
(пароль — из безопасного хранилища: `ПарольАдминистратораИзБезопасногоХранилища`).

Статусы ЛМ (`ОбщегоНазначенияИСМПКлиентСервер`):
`НеНастроено` → `Инициализация` → `Готово` | `ОшибкиСинхронизации`.

## 4. Документы УНФ (бизнес-цикл маркировки)

Создаются/проводятся **штатно в УНФ**; агент может работать с ними через
`unfAiAgent` (`CREATEDOCUMENT` / `EXECUTEQUERY` / `POSTDOCUMENT`).

| Документ | Роль в цикле |
|----------|--------------|
| `ЗаказНаЭмиссиюКодовМаркировкиСУЗ` | заказ на эмиссию КМ в СУЗ |
| `МаркировкаТоваровИСМП` | ввод в оборот (комиссия / производство) |
| `ПеремаркировкаТоваровИСМП` | смена КМ |
| `ПриемкаТоваровИСМП` | приёмка от поставщика (входящий УПД / коды) |
| `ОтгрузкаТоваровИСМП` | отгрузка (исходящий УПД / коды) |
| `РазрешениеНаОтгрузкуИСМП` | разрешительный режим |
| `СписаниеКодовМаркировкиИСМП` | списание КМ |
| `ВыводИзОборотаИСМП` | вывод (продажа конечному, экспорт, брак…) |
| `ВозвратВОборотИСМП` | возврат в оборот |
| `УточнениеСведенийОКодахМаркировкиИСМП` | уточнение сведений |
| `ПеремещениеМеждуМОДИСМП` | между модами / МОД |
| `ПодключениеКегаКОборудованиюРозливаИСМП` | пиво/кеги |
| `ОтчетИСМП` | отчёт/сверка |

Классификаторы/справочники:
`ВидыВозвратаВОборотИСМП`, `ПричиныВыводаИзОборотаИСМП`,
`ШаблоныКодовМаркировкиСУЗ`, `ШаблоныРазбораКодовМаркировкиИСМП`,
`КлючиАдресовИСМП`, `СтанцииУправленияЗаказамиИСМП`, `ИСМППрисоединенныеФайлы`.

**Типовой цикл:**
```
ЗаказНаЭмиссиюКодовМаркировкиСУЗ
  → (СУЗ) заказ → пул КМ → печать этикеток (ПечатьЭтикетокИСМП)
  → МаркировкаТоваровИСМП (ввод в оборот)
  → ПриемкаТоваровИСМП / ОтгрузкаТоваровИСМП
  → ВыводИзОборотаИСМП (розница / конечный потребитель)
```

## 5. Обработка штрихкода / разрешительный режим

Модули `ШтрихкодированиеИСМП`, `ШтрихкодированиеОбщегоНазначенияИСМП`,
`РазборКодаМаркировкиИСМПСлужебный`.

Ключевое поле результата: `ПроверкаНаЛокальномМодулеЧестныйЗнакЗавершена`
(булево). Если `Ложь` и требуется разрешительный режим — запрос идёт на **ЛМ ЧЗ**
(`ОбработатьАсинхронноШтрихкодНаЛокальномМодулеЧестныйЗнак`).

Типы кодов: потребительский КМ, групповой (агрегат), транспортный (≥18 символов).
Парсер: `РазборКодаМаркировкиИСМПСлужебныйКлиентСервер`.

## 6. Как работать ИИ-агенту (безопасный контур)

### 6.1 Через unfAiAgent HTTP (рекомендуется)

Агент **не** хранит сертификаты ЦРПТ и **не** вызывает CRPT напрямую.
Он читает/пишет данные УНФ; типовые модули сами общаются с ИС МП.

```http
POST http://localhost/unf/hs/ai/api
Basic obmen:203501
```

```json
{"command":"EXECUTEQUERY","query":"ВЫБРАТЬ ПЕРВЫЕ 20
  Док.Номер, Док.Дата, Док.Организация, Док.Комментарий
ИЗ Документ.ЗаказНаЭмиссиюКодовМаркировкиСУЗ КАК Док
ГДЕ НЕ Док.ПометкаУдаления
УПОРЯДОЧИТЬ ПО Док.Дата УБЫВ"}
```

Полезные запросы агенту:
- очередь/статусы заказов на эмиссию, `ОтчетИСМП`, `ПриемкаТоваровИСМП`
- настройки СУЗ: `РегистрСведений.НастройкиОбменаСУЗ`
- настройки ЛМ: `РегистрСведений.НастройкиПодключенияЛокальныхМодулейИСМП`
- ответственные за токены: `Справочник.ОтветственныеЗаАктуализациюТокеновАвторизацииИСМП`

Создание документов маркировки — **только черновик** (правило проекта
`CREATEDOCUMENT` → запись без проведения). Проведение — явное действие оператора.

### 6.2 Через EDT MCP (для разработки)

`read_module_source`, `search_in_code`, `get_metadata_objects` по проекту `UNF`.
Не использовать для боевого обмена с ЦРПТ.

### 6.3 Прямой HTTP к CRPT — только если явно сказано

Требует ЭЦП, ИНН организации, настроенного СУЗ. Никогда не логировать токены/пароли.

## 8. Gotchas

1. **ЭЦП обязательна** для ключа сессии ИС МП — без сертификата организации
   API `auth/cert` не работает.
2. **`clientToken` ≠ ключ сессии** — СУЗ и ИС МП используют разные токены.
3. **`omsId` обязателен** почти в каждом запросе СУЗ.
4. **Порт ЛМ 5995** — не 443; `ЗащищенноеСоединение` по умолчанию `Ложь`.
5. **Токен ПМСР истекает** — проверять `ДатаДействияТокенаПМСР`.
6. **Пароли ЛМ** — только из безопасного хранилища, не plain-text в коде.
7. **true-api** в пути — отдельный набор эндпоинтов (см. §2), не путать с `api/v3/...`.
8. **Test vs prod** — флаг `РежимРаботыСТестовымКонтуромИСМП` переключает хост.
9. **Агент не проводит документы маркировки** без явного запроса (правило create-only).
10. **Длинные коды** — транспортные упаковки ≥18 символов; групповые и
    потребительские разбираются разными шаблонами.

## 9. Превращение в скилл/действия агента

Из этого документа получаются агент-скиллы/интенты:

| Интент пользователя | Действие агента |
|---------------------|-----------------|
| «статус заказа на эмиссию» | `EXECUTEQUERY` по `ЗаказНаЭмиссиюКодовМаркировкиСУЗ` + `СтатусыБизнесЗаказов` (через 1С) |
| «остатки КМ / баланс GTIN» | `EXECUTEQUERY` / `GET_BALANCES`; при необходимости — через интерфейс `ИнтерфейсИСМП` |
| «проверь код маркировки» | разбор КМ (`РазобратьИНормализоватьКодМаркировки`) + статус; ЛМ — разрешительный режим |
| «выведи из оборота» | черновик `ВыводИзОборотаИСМП` (причина из `ПричиныВыводаИзОборотаИСМП`) |
| «настройка ЛМ ЧЗ / СУЗ» | прочитать/показать РС настроек; **не** менять токены/пароли агентом |
| «почему не проходит КМ» | лог `ПротоколОбменаИСМП`, статус ЛМ, `ПроверкаНаЛокальномМодулеЧестныйЗнакЗавершена` |

Формат SKILL.md для пакета — см. соседние скиллы `1c-unf-api`, `1c-http-services`.
При апдейте пакета: добавить `1c-chestny-znak` в `1cSkills/README.md` и, при
необходимости, короткий алиас-триггер в список запуска агента.

## 10. Чек-лист подключения (оператор)

1. Организация + **сертификат ЭЦП** загружены в 1С.
2. Договор с оператором Честный Знак (иначе «не подписан договор»).
3. Настроен **СУЗ** (`НастройкиОбменаСУЗ`, `omsId`, токен).
4. Для розницы: установлен **ЛМ ЧЗ**, заполнены `НастройкиПодключенияЛокальныхМодулейИСМП`,
   статус = `Готово`.
5. Тестовый контур — включить только в песочнице (`markirovka.sandbox.crptech.ru`).
6. Проверить `ЛогированиеЗапросовИСМП` перед боевым прогоном.
